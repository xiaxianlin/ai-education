# 题型与题目数据结构优化方案 V2

## 一、文档总结

### 1.1 K12在线练习APP题型设计指南

**核心设计原则**：
- **认知发展适配性**：根据皮亚杰认知发展理论，低年级以具体形象思维为主，高年级过渡到抽象逻辑思维
- **学科特点匹配**：语文侧重情境化建构，数学侧重操作-抽象过渡，英语侧重听说启蒙
- **交互性设计**：多样化交互方式（拖拽、连线、手写、语音）

**按学段的题型策略**：
| 学段 | 年龄 | 特点 | 建议 |
|------|------|------|------|
| 小学低段(1-3) | 6-9岁 | 具体形象思维，专注10-15分钟 | 图文结合、游戏化、即时反馈 |
| 小学高段(4-6) | 9-12岁 | 向抽象思维过渡 | 增加文字比重，引入应用题 |
| 初中(7-9) | 12-15岁 | 抽象逻辑思维 | 综合应用、跨学科融合 |
| 高中(10-12) | 15-18岁 | 形式运算思维 | 深度分析、创新思维 |

### 1.2 全学段题型设计策略

**七大题型功能模块**：
1. **选择题**：单选、多选、图片选择、听音选择
2. **拼写题**：字母拼写、单词拼写、拼音拼写
3. **口语题**：跟读、朗读、复述、对话
4. **判断题**：是非判断、正误判断
5. **匹配题**：连线、配对、拖拽匹配
6. **应用题**：计算应用、生活应用、综合应用
7. **简答题**：填空、短文填空、看图说话

**能力层次分布**：
- 识记层：约30-40%（基础知识点）
- 理解层：约35-45%（概念理解应用）
- 应用层：约20-30%（综合运用创新）

### 1.3 小学低年级三学科题型设计研究

**皮亚杰认知发展理论应用**：
- 6-8岁儿童处于前运算到具体运算的过渡期
- 思维依赖具体形象，难以理解抽象概念
- 注意力持续时间10-15分钟
- 词汇量约1000-3000字

**三学科差异化设计**：

| 学科 | 认知特点 | 题型设计要点 |
|------|----------|--------------|
| 语文 | 情境化建构 | 图画书、儿歌、看图写话、识字游戏 |
| 数学 | 操作-抽象过渡 | 实物操作、生活情境、一步应用题 |
| 英语 | 听说启蒙 | 语音模仿、图片配对、游戏化活动 |

**思维能力培养维度**：
1. 逻辑思维：分类归纳、演绎推理、空间想象
2. 批判性思维：信息辨别、逻辑判断
3. 创造性思维：想象力拓展、创意表达

### 1.4 低年级题型配置方案

**核心设计原则**：
1. 图文结合（图片占比30%-50%）
2. 游戏化设计（闯关、积分、徽章）
3. 即时反馈（声音、动画、鼓励语）
4. 渐进式学习（由易到难）
5. 多感官参与（视觉、听觉、触觉）

**JSON输出格式规范**：
```json
{
  "question_type": "大题型",
  "question_subtype": "小题型",
  "question": "题干内容",
  "options": [{"label": "A", "text": "选项内容"}],
  "resource_type": "image/audio",
  "resource_content": "资源描述",
  "answer": "标准答案",
  "difficulty": "简单/普通/困难",
  "knowledge": ["知识点"]
}
```

### 1.5 AI提示词库

**三种应用场景**：
| 场景 | 目标 | 题量 | 难度策略 | 时长 |
|------|------|------|----------|------|
| 日常训练 | 单一知识点强化 | 3-5题/组 | 聚焦单一难度 | 5-10分钟 |
| 单元测试 | 单元知识点检测 | 10-15题 | 易6:中3:难1 | 15-20分钟 |
| 综合评估 | 跨单元能力考查 | 15-20题 | 识记:理解:应用=5:8:7 | 25-40分钟 |

## 二、现有数据结构分析

### 2.1 现有 Question 表结构
```python
class Question:
    id: str                    # 题目ID
    subject: str               # 科目
    grade: int                 # 年级（1-6）
    type: str                  # 主类型
    subtype: str               # 子类型
    content: str               # 题目内容
    options: list[dict]        # 选项（JSON）
    answer: str                # 答案
    difficulty: str            # 难度
    resource: str              # 资源路径
    resource_type: str         # 资源类型
    resource_content: str      # 资源内容
    textbook_id: int           # 教材ID
    unit_id: int               # 单元ID
    prompt_id: int             # 提示词ID
    knowledge: str             # 知识点
```

### 2.2 现有 QuestionType 表结构
```python
class QuestionType:
    id: int                    # 题型ID
    title: str                 # 题型标题
    scene: str                 # 展现形式
    subject: str               # 科目
    grade: int                 # 年级（1-6）
    description: str           # 题型描述
    resource_type: str         # 资源类型
    prompt: str                # AI生成指令
```

### 2.3 存在的问题

1. **学段覆盖不足**：仅支持1-6年级，无法扩展到初高中
2. **交互配置缺失**：无法描述前端如何渲染和交互
3. **反馈机制缺失**：没有即时反馈、鼓励语等配置
4. **认知层次缺失**：没有识记/理解/应用的分类
5. **游戏化配置缺失**：无法配置积分、徽章、闯关等
6. **评估维度单一**：仅有难度，缺少多维能力评估
7. **资源类型单一**：仅支持image/audio，缺少video、animation等
8. **答案结构简单**：仅支持单一答案，不支持多答案、评分标准

## 三、优化方案设计

### 3.1 设计目标

1. **全学段兼容**：支持K12全部学段（1-12年级）
2. **前端交互驱动**：数据结构直接驱动前端渲染
3. **多维能力评估**：支持认知层次、能力维度的标注
4. **游戏化支持**：内置游戏化元素配置
5. **灵活可扩展**：通过JSON Schema支持新题型扩展
6. **AI生成友好**：便于AI理解和生成符合规范的题目

#### 3.3.2 Question（题目表）

```sql
CREATE TABLE ah_question_v2 (
  id VARCHAR(36) PRIMARY KEY COMMENT 'UUID',

  -- 题目内容
  stem JSON NOT NULL COMMENT '题干（支持富文本）',
  options JSON COMMENT '选项列表',
  blanks JSON COMMENT '填空位置配置',
  
  -- 资源
  resources JSON COMMENT '资源列表（多资源支持）',
  
  -- 答案
  answer JSON NOT NULL COMMENT '答案配置',
  explanation TEXT COMMENT '解析',
  
  -- 难度与认知
  difficulty VARCHAR(20) NOT NULL COMMENT '难度：easy/medium/hard',
  cognitive_level VARCHAR(20) COMMENT '认知层次',
  
  -- 知识点
  knowledge_points JSON COMMENT '知识点列表',
  ability_tags JSON COMMENT '能力标签',
  
  -- 来源
  source VARCHAR(50) DEFAULT 'ai' COMMENT '来源：ai/manual/import',
  prompt_id INT COMMENT '生成此题的Prompt ID',

  usage_count INT DEFAULT 0 COMMENT '使用次数',

```

**stem（题干）结构**：
```json
{
  "text": "看图片，选择正确的拼音。",
  "rich_text": "<p>看图片，选择正确的<b>拼音</b>。</p>",
  "audio_url": "https://...",           // 题干朗读
  "highlight_words": ["拼音"],          // 高亮词汇
  "hints": ["注意看图片中是什么"],       // 提示
  "sub_questions": []                   // 复合题的子题（详见下方）
}
```

**sub_questions（子题）结构 - 用于复合题/应用题**：

复合题（如应用题）包含多个小题，每个小题可以有独立的交互类型和答案：

```json
{
  "sub_questions": [
    {
      "id": "sub_1",                           // 子题ID
      "order": 1,                              // 显示顺序
      "stem": {                                // 子题题干
        "text": "（1）小明现在一共有多少个苹果？",
        "hints": ["注意：先算加法"]
      },
      "interaction_type": "text_input",        // 子题交互类型（可与父题不同）
      "interaction_config": {                  // 子题交互配置
        "input_type": "number",
        "placeholder": "请输入数字"
      },
      "options": null,                         // 选择题才有选项
      "resources": [],                         // 子题专属资源（可选）
      "answer": {                              // 子题答案
        "type": "exact",
        "correct_answers": ["8"],
        "accept_answers": ["8个", "八", "八个"],
        "scoring": { "full_score": 5 }
      },
      "explanation": "5 + 3 = 8，所以小明现在有8个苹果。"
    },
    {
      "id": "sub_2",
      "order": 2,
      "stem": { "text": "（2）如果小明吃掉2个，还剩多少个？" },
      "interaction_type": "single_choice",     // 第二小题是选择题
      "options": [
        { "id": "A", "text": "5个", "is_correct": false, "feedback": "计算一下：8-2=?" },
        { "id": "B", "text": "6个", "is_correct": true, "feedback": "正确！8-2=6" },
        { "id": "C", "text": "7个", "is_correct": false, "feedback": "再算算看" }
      ],
      "answer": {
        "type": "exact",
        "correct_answers": ["B"],
        "scoring": { "full_score": 5 }
      },
      "explanation": "8 - 2 = 6，还剩6个苹果。"
    }
  ]
}
```

**复合题答案结构**（父题级别）：
```json
{
  "type": "composite",                         // 复合题类型
  "scoring": {
    "full_score": 10,                          // 总分
    "partial_strategy": "sum",                 // 计分策略：sum(累加) / all_or_nothing(全对才得分)
    "sub_scores": {                            // 子题分值分布
      "sub_1": 5,
      "sub_2": 5
    }
  }
}
```

**复合题设计要点**：

| 设计点 | 说明 |
|--------|------|
| 子题独立交互 | 每个子题可以有不同的 `interaction_type`（填空、选择、判断混合） |
| 独立评分 | 每个子题有自己的 `answer.scoring`，父题汇总计算 |
| 资源共享 | 父题 `resources` 对所有子题可见（如共享阅读材料） |
| 子题专属资源 | 子题可以有自己的 `resources`（如子题配图） |
| 计分策略 | `sum` 累加子题得分；`all_or_nothing` 全对才得满分 |
| 顺序控制 | `order` 字段控制子题显示和答题顺序 |

```tsx
interface QuestionProps {

  questionType: QuestionType;

  onSubmit: () => void;

function QuestionRenderer({ question, questionType, onAnswer, disabled }: QuestionProps) {
  // 1. 渲染题干
  const stemElement = <StemRenderer stem={question.stem} resources={question.resources} />;
  
  // 2. 渲染资源
  const resourceElements = question.resources
    ?.filter(r => r.position === 'stem')
    .map(r => <ResourceRenderer key={r.id} resource={r} />);
  
  // 3. 根据交互类型选择答题组件
  const InteractionComponent = INTERACTION_COMPONENT_MAP[questionType.interaction_type];
  const interactionElement = (
    <InteractionComponent
      config={questionType.interaction_config}
      options={question.options}
      blanks={question.blanks}
      disabled={disabled}
      onChange={onAnswer}
    />
  );
  
  return (
    <div className="question-container">
      {stemElement}
      {resourceElements}
      {interactionElement}
    </div>
  );
}
```

#### 3.4.3 复合题渲染组件

当题目包含 `stem.sub_questions` 时，使用复合题渲染模式：

```tsx
interface CompositeQuestionProps {
  question: QuestionV2;
  questionType: QuestionTypeV2;
  onSubAnswer: (subId: string, answer: Answer) => void;
}

function CompositeQuestionRenderer({ question, questionType, onSubAnswer }: CompositeQuestionProps) {
  const subQuestions = question.stem.subQuestions || [];
  
  // 子题答案状态
  const [subAnswers, setSubAnswers] = useState<Record<string, any>>({});
  
  const handleSubAnswer = (subId: string, answer: any) => {
    setSubAnswers(prev => ({ ...prev, [subId]: answer }));
    onSubAnswer(subId, answer);
  };
  
  return (
    <div className="composite-question">
      {/* 共享题干和资源 */}
      <div className="shared-stem">
        <StemRenderer stem={question.stem} />
        {question.resources
          ?.filter(r => r.position === 'stem')
          .map(r => <ResourceRenderer key={r.id} resource={r} />)}
      </div>
      
      {/* 子题列表 */}
      <div className="sub-questions">
        {subQuestions
          .sort((a, b) => a.order - b.order)
          .map((subQ) => (
            <SubQuestionCard key={subQ.id} subQuestion={subQ}>
              {/* 子题题干 */}
              <div className="sub-stem">{subQ.stem.text}</div>
              
              {/* 子题专属资源 */}
              {subQ.resources?.map(r => <ResourceRenderer key={r.id} resource={r} />)}
              
              {/* 子题答题组件（根据子题的交互类型选择） */}
              <AnswerFormFactory 
                interactionType={subQ.interactionType}
                config={subQ.interactionConfig}
                options={subQ.options}
                value={subAnswers[subQ.id]}
                onChange={(ans) => handleSubAnswer(subQ.id, ans)}
              />
            </SubQuestionCard>
          ))}
      </div>
    </div>
  );
}

// 判断是否为复合题
function isCompositeQuestion(question: QuestionV2): boolean {
  return (question.stem.subQuestions?.length || 0) > 0;
}

// 主渲染入口
function QuestionRenderer({ question, questionType, ...props }) {
  if (isCompositeQuestion(question)) {
    return <CompositeQuestionRenderer question={question} questionType={questionType} {...props} />;
  }
  return <SimpleQuestionRenderer question={question} questionType={questionType} {...props} />;
}
```

## 九、总结

本优化方案主要改进：

1. **全学段支持**：通过 `stage` 和扩展的 `grade`（1-12）支持K12全学段
2. **交互驱动**：引入 `interaction_type` 和 `interaction_config` 直接驱动前端渲染
3. **多维评估**：增加 `cognitive_level` 和 `ability_dimensions` 支持能力评估
4. **游戏化配置**：通过 `feedback_config` 支持即时反馈、动画、音效等
5. **灵活资源**：支持多资源、多位置、多类型的资源配置
6. **AI生成友好**：结构化的 `output_schema` 和模板系统
7. **向后兼容性**：新旧表并存，支持渐进式迁移

该方案完全基于文档中的设计原则，特别考虑了：
- 皮亚杰认知发展理论的应用
- 不同学科的差异化设计需求
- 前端交互的实现便利性
- AI生成的规范化输出
