## 一、功能概述

实现练习完成后 AI 自动生成综合评估报告的完整闭环：学生完成练习 → 后端立即生成基础分数报告 → 异步入队 `report.generate` 任务 → AI (Gemini) 分析答题数据生成详细报告（优势、薄弱项、建议、能力分解等） → 更新数据库报告记录 → 前端展示完整 AI 报告。学生端和管理端均可查看报告。

## 四、核心数据表

```sql
CREATE TABLE ah_practice_report (
    id                   BIGINT PRIMARY KEY AUTO_INCREMENT,
    session_id           VARCHAR(64) NOT NULL,
    student_id           VARCHAR(64) NOT NULL,
    total_questions      INT NOT NULL DEFAULT 0,
    correct_questions    INT NOT NULL DEFAULT 0,
    total_time           INT NOT NULL DEFAULT 0,       -- 用时(秒)
    overall_score        DOUBLE NOT NULL DEFAULT 0,    -- 总评分 (0-100)
    current_ability      DOUBLE NOT NULL DEFAULT 0,    -- 能力值
    confidence           DOUBLE NOT NULL DEFAULT 0,    -- 置信度
    ability_level        VARCHAR(32) DEFAULT '',       -- 能力等级标签
    percentile           INT NOT NULL DEFAULT 0,       -- 百分位
    knowledge_scores     JSON,                          -- 知识点得分 (map)
    question_distribution JSON,                         -- 题目分布 (map)
    ability_breakdown    JSON,                          -- 能力分解 (map)
    learning_speed       DOUBLE NOT NULL DEFAULT 0,    -- 学习速度
    consistency          DOUBLE NOT NULL DEFAULT 0,    -- 稳定性
    strengths            JSON,                          -- 优势列表 (string[])
    weaknesses           JSON,                          -- 薄弱项列表 (string[])
    recommendations      JSON,                          -- 改进建议 (string[])
    create_time          BIGINT NOT NULL,
    update_time          BIGINT DEFAULT NULL,
    UNIQUE KEY uk_session (session_id)
);
```

## 五、关键业务逻辑

### 5.1 报告生成流程

```
学生提交最后一题
       │
       ▼
  Complete()
  ├─ 1. 更新 session status = completed
  ├─ 2. buildReport() → 基础报告 (overall_score = correct/total * 100)
  ├─ 3. CreateReport() → INSERT 基础报告到 DB
  ├─ 4. NewReportGenerateTask() → 构建异步任务 payload
  ├─ 5. Enqueue() → 入队 (失败仅 WARN，不阻塞主流程)
  └─ 6. updateMasteryAfterComplete() → 更新掌握度 (独立 side-effect)
       │
       ▼
  [Worker] report.generate handler
  ├─ 1. 校验 payload (session_id, student_id)
  ├─ 2. 获取 session → 校验状态 = completed + 归属
  ├─ 3. GetPracticeData() → 获取答案数据
  ├─ 4. AI.GenerateReport() → 调用 Gemini 生成 PracticeReportDraft
  │     ├─ 输入：session 信息 + 答题结果 + 用时
  │     └─ 输出：overall_score, strengths[], weaknesses[], recommendations[],
  │              ability_breakdown, knowledge_scores, ...
  ├─ 5. UpdateReport() → UPDATE 报告记录，覆盖 AI 字段
  └─ 6. 错误返回 → Redis 自动重试
```

### 5.2 双模式 Handler 注册

```
┌─ Development (in-process) ───────────────────────────┐
│  cmd/api/main.go                                       │
│  1. 创建 DispatchEnqueuer + Registry                   │
│  2. 注册 practice.generate handler                      │
│  3. 创建 practiceService (注入 aiProvider)               │
│  4. 注册 report.generate handler → DispatchEnqueuer    │
│  5. 任务同步执行（无 Redis）                             │
└────────────────────────────────────────────────────────┘

┌─ Production (Redis Worker) ───────────────────────────┐
│  cmd/worker/main.go                                    │
│  1. 连接 Redis                                         │
│  2. 创建 Registry                                      │
│  3. 注册 practice.generate handler                      │
│  4. 创建 reportService (仅注入 aiProvider)               │
│  5. 注册 report.generate handler                        │
│  6. Worker.Start() → 消费 Redis 队列                    │
└────────────────────────────────────────────────────────┘
```

### 5.3 前端 JSON 解析架构

```
后端返回 (JSON string fields)
       │
       ▼
shared-web/report.ts
  parseReport(report) → ParsedReport
  ├─ safeParseJSON(report.strengths, [])     → string[]
  ├─ safeParseJSON(report.weaknesses, [])    → string[]
  ├─ safeParseJSON(report.recommendations, []) → string[]
  ├─ safeParseJSON(report.ability_breakdown, {}) → Record<string,unknown>
  └─ safeParseJSON(report.knowledge_scores, {}) → Record<string,unknown>
       │
       ▼
Model 层 (useMemo)
  report = parseReport(detail?.report)
  hasAIReport = hasAIReportContent(report)
       │
       ▼
View 层
  接收 ParsedReport（已类型化）
  直接渲染 strengths.map(), weaknesses.map()...
```

## 七、代码审查要点

- [x] **安全**: `HandleReportGenerate` 校验 session_id、student_id、归属关系和状态，防御越权
- [x] **非阻塞**: `Complete()` 中入队失败仅 WARN，不影响主流程返回报告 ID
- [x] **幂等**: `CreateReport()` 使用 `session_id` UNIQUE KEY，重复调用返回已有报告
- [x] **接口最小化**: `NewReportGenerateHandler` 接受 `ReportGenerateHandler` 最小接口，而非 `*Service`
- [x] **JSON 解析安全**: 前端所有 JSON 字段通过 `safeParseJSON` 解析，带 fallback 值
- [x] **数值空保护**: 前端渲染 `(overall_score ?? 0).toFixed(1)` 防止 null/undefined
- [x] **双模式兼容**: in-process 和 Redis worker 两种模式都注册了 handler

## 九、设计决策

- **Create + Update 分离**: `CreateReport()` 在 `Complete()` 中同步写入基础统计，`UpdateReport()` 在 AI 生成后异步更新。避免 AI 超时导致基础数据丢失。
- **variadic ReportGenerator**: `NewService()` 使用 variadic 参数接收 `ReportGenerator`，不破坏 `cmd/worker/main.go` 中 `NewService(repo, nil, nil)` 的调用。
- **最小接口 Handler**: `NewReportGenerateHandler` 只依赖 `HandleReportGenerate` 方法，与 `*Service` 的其他方法解耦，便于单独测试。
- **shared-web 集中解析**: `parseReport()` 放在 `@ai-education/shared-web`，student-web 和 admin-web 共用，避免重复代码。
