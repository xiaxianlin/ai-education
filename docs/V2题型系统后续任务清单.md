### 四、数据迁移和同步（中优先级）

#### 4.1 清理重复数据
**目标**: 清理迁移过程中产生的重复数据

- [ ] **数据检查**
  - 运行 `check_sync_status.py` 检查数据一致性
  - 识别重复的 V2 题型记录
  - 生成清理 SQL 脚本

- [ ] **数据清理**
  - 执行清理脚本删除重复数据
  - 验证清理后的数据完整性
  - 更新数据统计

**SQL 脚本**:
```sql
-- 删除重复的 V2 题型（保留最早的记录）
DELETE t1 FROM ah_question_type_v2 t1
INNER JOIN ah_question_type_v2 t2
WHERE t1.id > t2.id AND t1.code = t2.code;
```

#### 4.2 启用双写同步
**目标**: 逐步启用 V1 → V2 双写功能

- [ ] **功能开关**
  - 在 `.env` 中设置 `USE_QUESTION_V2_SYNC=true`
  - 监控双写性能影响
  - 处理双写失败的回滚逻辑

- [ ] **数据验证**
  - 验证新创建的 V1 题目是否同步到 V2
  - 检查数据一致性
  - 修复同步失败的数据

**配置文件**:
```
apps/server/.env
USE_QUESTION_V2_SYNC=true  # 启用双写
USE_QUESTION_V2=false      # 暂不启用 V2 读取
```

## 🔍 技术债务和注意事项

### 已知问题
1. **重复数据**: V2 题型表中有 270 条记录（应为 135 条），需要清理
2. **类型映射**: 部分交互类型尚未实现，需要补充组件
3. **错误处理**: 部分 API 错误处理不够完善，需要加强

### 性能优化点
1. **数据库索引**: 检查并优化 V2 表的索引
2. **查询优化**: 优化复杂查询的 SQL
3. **缓存策略**: 考虑添加题型和题目的缓存

### 安全考虑
1. **输入验证**: 加强前端和后端的输入验证
2. **权限控制**: 确保 API 权限检查完善
3. **数据脱敏**: 敏感数据需要脱敏处理
