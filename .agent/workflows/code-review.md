# 代码审查要点

## 类型安全

### TypeScript

- ✅ 所有函数都有明确的类型定义
- ✅ 组件 Props 使用接口定义
- ✅ 避免使用 `any` 类型
- ✅ API 响应类型与后端 Schema 一致

### Python

- ✅ 所有函数都有类型提示
- ✅ 使用 Pydantic Schema 进行数据验证
- ✅ 数据库模型使用 SQLAlchemy 类型注解

## 错误处理

- ✅ 所有 API 调用都有错误处理
- ✅ 异步操作都有 try-catch 或错误回调
- ✅ 错误信息对用户友好
- ✅ 关键错误记录日志

## 代码质量

### 可读性

- ✅ 函数和变量命名清晰
- ✅ 代码有适当的注释
- ✅ 复杂逻辑有解释说明

### 可维护性

- ✅ 遵循单一职责原则
- ✅ 代码结构清晰，目录组织合理
- ✅ 避免重复代码（DRY 原则）

### 性能

- ✅ 数据库查询优化（避免 N+1 查询）
- ✅ 前端组件使用 memo 优化
- ✅ 图片和资源使用缓存

## 安全性

- ✅ 所有 API 端点有适当的认证和授权
- ✅ 用户输入都经过验证和清理
- ✅ 敏感信息不暴露在日志中
- ✅ 使用环境变量管理配置

## 代码风格

- ✅ 遵循项目的代码风格规范
- ✅ 导入顺序符合规范
- ✅ **所有导入必须在文件头部**（禁止在函数内部导入）
- ✅ **避免在函数内定义函数**（应提取到模块级别）

## 架构遵循

- ✅ 遵循分层架构（路由层 → 服务层 → 数据层）
- ✅ 遵循页面目录结构（models/views/hooks/components）
- ✅ 遵循状态管理模式（unstated-next + ahooks）
- ✅ 遵循 SQLAlchemy 2.0 ORM 风格（后端）
