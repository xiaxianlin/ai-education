## 项目架构概览

### Monorepo 结构
```
ai-eduaction/
├── apps/                    # 应用层
│   ├── admin-web/          # 管理端前端
│   ├── student-web/        # 学生端 Web
│   ├── student-app/        # 学生端移动应用
│   ├── server-api/         # API 服务
│   └── server-task/        # 任务服务
├── packages/                # 共享包层
│   └── shared-frontend/     # 前端共享类型和工具
└── infra/                   # 基础设施
    ├── mysql/              # 数据库初始化
    └── nginx/              # Nginx 配置
```

### 技术架构

#### 前端架构
- **管理端**: React + Rsbuild + Ant Design
- **学生端 Web**: React + Rsbuild + shadcn/ui + Tailwind
- **学生端移动**: React Native + NativeWind + React Navigation
- **共享**: TypeScript 类型定义 (`packages/shared-frontend`)

#### 后端架构
- **API 服务**: FastAPI + SQLAlchemy + MySQL + Redis
- **任务服务**: FastAPI + Redis Queue
- **认证**: JWT Token
- **存储**: 阿里云 OSS
- **AI**: 阿里云百炼AI

### 数据流架构

```
前端/移动端 → API Gateway (Nginx) → server-api → MySQL
                                    ↓
                              Redis (缓存)
                                    ↓
                              server-task (异步任务)
```

## 架构原则

1. **关注点分离**: 前后端分离，API 服务与任务服务分离
2. **模块化**: Monorepo 结构，各应用独立开发和部署
3. **可扩展性**: 支持水平扩展和功能扩展
4. **可维护性**: 清晰的代码结构和文档
5. **性能优先**: 缓存策略、数据库优化、前端性能优化
6. **安全性**: 认证授权、数据验证、安全传输
7. **一致性**: 跨项目代码风格和架构模式一致

## 技术决策

### 前端技术选型

#### 为什么选择 React？
- 生态丰富，组件库完善
- 团队熟悉度高
- 跨平台支持（Web + React Native）

#### 为什么选择 Rsbuild？
- 构建速度快
- 配置简单
- 与 Vite 兼容性好

#### 为什么选择 Monorepo？
- 代码共享方便（shared-frontend）
- 统一版本管理
- 便于跨项目重构

### 后端技术选型

#### 为什么选择 FastAPI？
- 性能优秀（基于 Starlette）
- 自动 API 文档
- 类型提示支持好
- 异步支持完善

#### 为什么分离 API 服务和任务服务？
- 职责分离：API 服务处理同步请求，任务服务处理异步任务
- 独立扩展：任务服务可以独立扩展 worker
- 故障隔离：任务服务故障不影响 API 服务

### 数据库设计原则

1. **规范化**: 遵循数据库范式，减少冗余
2. **索引优化**: 为常用查询字段建立索引
3. **异步操作**: 使用 SQLAlchemy 异步 ORM
4. **连接池**: 合理配置数据库连接池

### 缓存策略

1. **Redis 缓存**: 
   - 热点数据缓存
   - Session 存储
   - 分布式锁

2. **前端缓存**:
   - React Query 缓存
   - 浏览器缓存策略

## 最佳实践

1. **设计优先**: 先设计架构，再实现代码
2. **文档驱动**: 重要决策和架构设计要有文档
3. **渐进式演进**: 避免大规模重构，渐进式改进
4. **性能监控**: 建立性能基线，持续监控
5. **安全审查**: 定期进行安全审查
6. **技术选型**: 基于项目需求和团队能力选择技术
7. **代码复用**: 通过共享包减少重复代码
8. **测试覆盖**: 关键路径要有测试覆盖
